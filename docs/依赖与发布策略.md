# 依赖与发布策略

## 依赖更新

仓库使用 `renovate.json` 维护依赖更新策略：默认每月检查，依赖发布至少 7 天后再升级，开发依赖的 minor/patch 合并处理，生产依赖 major 必须在 Dependency Dashboard 人工批准。锁文件维护也按月执行。

每次依赖升级必须保留 `package.json` 与 `pnpm-lock.yaml` 的同一提交，并通过 typecheck、lint、SQLite 全量测试、构建、tarball 检查及 SBOM 生成。数据库驱动或 Knex 升级还必须同步 `docs/数据库驱动兼容性.md`，并重新运行对应驱动契约。

## 发布门禁

日常验证使用：

```bash
npm run verify
npm run build
npm run pack:check
npm run package:smoke
npm run security:scan
npm run sbom
npm run release:check:metadata
```

`npm run sbom` 从 `pnpm-lock.yaml` 的生产依赖闭包生成 CycloneDX 1.5 文件 `artifacts/sbom.cdx.json`。该目录不提交 Git，也不进入 npm tarball；CI 应把它作为对应 release 的构建附件保留。生成器遇到缺失的锁定依赖会直接失败，不能输出不完整依赖图。

`npm run package:smoke` 会创建全新的临时 npm 项目，只安装当前 tarball 与 `better-sqlite3`，先以 `npm ls --omit=dev --all` 验证生产依赖树，再执行包入口导入、SQLite 内存迁移、带自定义列名和默认值的 CRUD，以及失败事务回滚。临时项目执行后自动删除；下载缓存位于被 Git 忽略的 `artifacts/npm-smoke-cache`，用于避免本地重复下载。

`npm run security:scan` 对工作树和 npm dry-run 文件清单执行凭据、token、数据库 URI、绝对数据库路径、邮箱、手机号及数据库产物检查。允许项必须在 `security-scan-allowlist.json` 中按规则、路径和范围登记原因，不能通过代码中的模糊正则静默跳过。扫描输出不会包含匹配原文。完整历史由 `npm run security:scan:history` 单独审计，详见 `docs/安全扫描报告.md`。

正式发布使用 `npm run release:verify`，它在上述检查后执行严格门禁：

- HEAD 必须具有与 `package.json` 完全一致的 `v<version>` tag。
- 工作树必须干净，包含未跟踪文件检查。
- `CHANGELOG.md` 必须存在对应版本章节。
- npm 包必须包含 `dist`、`LICENSE`、`NOTICE` 和 `CHANGELOG.md`。
- registry 固定为公开 npm registry，公开 scoped package 使用 public access。
- 发布必须运行在 npm provenance 支持的 GitHub Actions 或 GitLab CI 云托管环境，且 `repository` 必须与 CI 项目匹配。

`prepublishOnly` 会再次执行严格门禁；`npm run pub` 使用 `npm publish --provenance --access public`。发布脚本不会读取或保存长期 npm token。

`npm run log` 根据 Conventional Commit 标题生成当前 `package.json.version` 对应章节。已有同版本章节会被替换而不是重复追加；没有规范提交或版本号非法时不会写文件。生成内容先写入同目录临时文件，读取校验成功后才原子替换 `CHANGELOG.md`，因此生成失败不会留下半个版本章节。

## 当前外部阻塞

公开主仓库已确定为 `https://github.com/ZMmouse/lli-db`，`package.json.repository`、homepage 和 bugs 已同步。公开仓库采用当前安全工作树生成的全新初始提交，不携带 Gitee 私有仓库的历史对象、分支或 tag。维护者仍需完成以下外部配置，才能声明 provenance 已真正启用：

1. 在 GitHub 全新历史上启用分支保护，并确认仓库中不存在来自 Gitee 的旧 refs。
2. 配置 npm trusted publishing，优先使用短期 OIDC，不保存长期写入 token。
3. CI 发布任务授予 OIDC/id-token 权限，仅响应受保护的版本 tag。
4. 上传 `artifacts/sbom.cdx.json`，发布后使用 `npm audit signatures` 验证签名和 attestation。

在这些条件完成前不要绕过 `release:check` 手工发布；设置 `publishConfig.provenance: true` 只是安全默认值，不代表当前包已经产生公开 provenance。
