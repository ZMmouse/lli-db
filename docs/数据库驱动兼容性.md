# 数据库驱动兼容性

本页记录 `@llii/db 0.1.0` 的 Knex client 支持边界。只有进入自动化契约套件的组合才标记为“已支持”；能由 Knex 创建但尚未完成本项目验证的组合标记为“预览”，不能据此推断生产兼容性。

| Knex client | 数据库 | 驱动版本 | Knex 版本 | 状态 | 当前验证 |
|---|---|---:|---:|---|---|
| `better-sqlite3` | SQLite | `^12.5.0` | `^3.1.0` | 已支持 | 模型迁移、CRUD、重复键字段映射、事务回滚、关联、分页、故障恢复 |
| `sqlite3` | SQLite | `^5.1.7` | `^3.1.0` | 预览 | 接受配置并统一 SQLite 错误别名，但未运行完整契约套件 |
| `pg` / `postgres` / `postgresql` | PostgreSQL | `^8.16.3` | `^3.1.0` | 预览 | 当前没有容器测试，不声明 CRUD、DDL 或并发迁移兼容 |
| 其他 client | 未定义 | 未定义 | `^3.1.0` | 不支持 | `Database` 构造时抛出 `LLI400`，不会再依赖 Knex 的模糊加载错误 |

版本范围表示当前源码和自动化环境针对的兼容范围，不等于所有范围内版本均已逐个验证。锁文件中的精确版本是本次发布验证基线。

## 驱动契约

每个升级为“已支持”的驱动至少必须通过同一组测试：

1. 初始化连接与模型迁移。
2. create、find、update、delete 基础 CRUD。
3. unique 冲突转换为包含模型字段 code 的 `LLI40010`。
4. 事务失败后完整回滚。
5. 字段差异迁移、失败快照与重试。
6. 关联写入和 populate。
7. 分页上限与参数边界。

当前 `test/driver-compatibility.test.ts` 提供 SQLite 的最小驱动 smoke contract，其余 SQLite 测试覆盖完整行为。增加 PostgreSQL 支持时，应复用相同断言并在临时容器中运行，不能连接固定开发或公网数据库。

## 升级规则

- Knex 或数据库驱动升级必须先修改兼容矩阵，再运行该驱动完整契约。
- 未通过完整契约的驱动只能保持“预览”，README 不得写成正式支持。
- 新增 MySQL 等数据库前，需先处理错误码、DDL 差异、返回值及事务语义，不能仅因 Knex 可连接就列为兼容。
