# 仓库数据文件策略

## 当前策略

- 仓库不允许跟踪 `.db`、`.db3`、`.s3db`、`.sqlite`、`.sqlite3` 及其 journal/WAL/SHM 文件。
- 当前数据库文件白名单为空；如将来确实需要二进制 fixture，必须先完成匿名化评审并在自动化测试中显式登记。
- SQLite 测试数据由测试代码写入系统临时目录，测试结束后销毁，不依赖仓库快照。
- 示例数据库默认在运行目录生成，也可通过 `LLI_DB_EXAMPLE_PATH` 指向开发者自己的本地路径。

## 本次审计结论

原 `data.sqlite3` 是运行残留，不是稳定 fixture：它包含已填充的用户身份、联系信息和密码字段，关联数据量也已随运行发生漂移。当前工作树已删除该文件，并通过 `.gitignore` 和回归测试阻止同类文件再次进入仓库。

## 历史清理

当前提交删除文件后，旧 Git 提交仍可能保留其二进制内容。发布前应在干净工作树中使用经过评审的历史重写工具移除所有历史中的 `data.sqlite3`，复核远程差异后再使用 `git push --force-with-lease` 更新远程分支。历史重写后，协作者必须重新克隆或按新历史重置本地仓库。
