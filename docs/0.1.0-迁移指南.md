# 0.1.0 迁移指南

本指南记录审计修复期间已经确定的公开契约变化。升级前请先在 SQLite 隔离数据库运行完整测试；PostgreSQL 契约仍待单独验证。

## 查询参数

- 新代码统一使用 `where`。`filters` 暂时保留为弃用别名；两者同时传入时按 AND 合并。
- `select`、`populate`、`data`、分页参数不再接受任意类型，错误结构会在 TypeScript 编译阶段失败。
- `returning(fieldCode)` 接收模型字段 code，并自动转换自定义 `columnName`。
- 查询及写入不会再修改调用方传入的 `data`、`where`、`select` 或 `populate`。
- `updateMany` 不再允许省略或传入空的 `where/filters`；有意更新全表时必须显式设置 `allowAll: true`。
- `page/pageSize` 必须成对出现，不能与 `limit/offset` 混用；所有分页值必须是安全整数并受 `query.maxPageSize`、`query.maxLimit`、`query.maxOffset` 限制。
- populate 会按 `query.populateBatchSize` 分批查询关联 ID，默认每批 500 个；批次顺序执行并合并后再绑定到主记录。
- 本版本不新增 cursor API：当前模型缺少稳定唯一排序元数据，先保留受上限保护的 page/offset 分页，避免提供不可靠的游标契约。

## `findOne` 判空

`findOne` 的返回类型从 `Promise<T>` 修正为 `Promise<T | null>`。调用方必须显式处理未找到记录：

```typescript
const user = await db.query<User>('user').findOne({ where: { id } });
if (!user) return null;

console.log(user.username);
```

不建议使用非空断言绕过检查，除非“不存在”已经由同一事务内的约束保证。

## 事务回调

- 事务回调参数现在使用公开的 `ITransactionContext`。
- `db.transaction(callback)` 会推导并返回 callback 的结果类型；`db.transaction()` 返回 `ITransactionObject`。
- `onCommit`/`onRollback` 只接受无参数的同步或异步函数，并会等待全部回调完成。
- 提交回调失败时数据库已经提交，不会再次回滚；回滚回调失败时，事务主体错误保存在回调错误的 `cause`。

## 时间戳

创建时显式传入的 `createdAt`/`updatedAt` 保留。`update` 和 `updateMany` 会始终用系统当前时间覆盖 `updatedAt`。

## 生命周期

生命周期事件使用 `beforeCreate`、`afterCreate` 等 `before/after + 操作名` 名称。旧的、未执行的 `create/update/findOne` 订阅键不再属于生命周期类型；操作级扩展仍可使用 Middleware API。

## 诊断接口

- `Database` 新增 `diagnostics.logger`、`diagnostics.onEvent` 配置和 `db.onDiagnostic()` 动态订阅接口。
- 查询与迁移提供 start/success/error 事件；迁移还提供逐模型事件。
- 默认不再调用 `console.error`。诊断事件不会包含 SQL、bindings、业务数据、错误 message 或 stack。
- logger/监听器只用于旁路观察，其同步异常和异步拒绝不会影响数据库操作。

## 类型生成

`ModelTableMigrator` 现在可从包根导入。配置 `canGenerateType: true` 后，类型文件在 `syncAll()` 成功后写入 `appRoot/typeOutDir`；关闭开关不会创建目录。

迁移执行前应先调用 `migrator.dryRun()` 审核计划。删列和可能重写现有数据的字段类型、长度、required 变更现在默认被拒绝；备份并验证恢复后，改用 `migrator.syncAll({ allowDestructive: true })` 显式确认。该参数是安全确认，不会自动创建备份。字段 `type` 变化现在也会进入差异检测和 DDL 更新。

同一进程内，指向同一 SQLite 文件的多个 `Database` 实例会共用迁移锁；`:memory:` 数据库仍按实例隔离。跨进程锁和 PostgreSQL 行为尚未验证，部署时仍需外部互斥。详见 `docs/迁移运维指南.md`。

数据库驱动现在具有明确兼容矩阵。`better-sqlite3` 是当前唯一完成项目契约验证的 client；`sqlite3` 与 PostgreSQL 别名暂为预览。矩阵外的 client（包括尚未支持的 MySQL）会在 `Database` 构造阶段抛出 `LLI400`。此前依赖 Knex 隐式加载其他驱动的项目，需要在升级前保留旧版本或先补齐该驱动契约。详见 `docs/数据库驱动兼容性.md`。

发布流程新增 CycloneDX SBOM、版本 tag/CHANGELOG/干净工作树检查和 provenance 强制配置。公开仓库与 GitHub Actions 工作流已经就绪，但仍需在 npm 包设置中登记 `publish.yml` trusted publisher，并在 GitHub 配置受保护的 `npm` Environment 和版本 tag；完成前不要手工绕过严格发布门禁。详见 `docs/依赖与发布策略.md`。

`tslib` 从开发依赖移动到生产依赖。项目启用了 TypeScript `importHelpers`，旧依赖分类会导致干净安装后的 `dist` 在导入时报告 `Cannot find module 'tslib'`；当前 tarball smoke 已固定该回归。
